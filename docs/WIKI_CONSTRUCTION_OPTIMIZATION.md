# Wiki构建增量算法优化与nashsu对比

> 说明：本文的量化数字来自 mobilework 构建引擎所移植的参考实现（new-wiki）的历史本机测量，用于说明算法特性，未在 mobilework 重构后重新跑分。构建侧逻辑基本原样保留，故结论仍具代表性；如需正式基准，由评测组（`benchmarks/`）在统一环境重测。

## 一眼结论

> 本次优化把维护粒度从“文件→页面”细化为“文件→Chunk→Claim→页面”。当文档只有5%内容变化时，送给后续语义维护的新增文本量减少约95%；删除时可按Claim清理，不再只能删来源字段或整页重写。

## 已实现

| 算法 | 实现结果 | 直接价值 |
|---|---|---|
| 声明级来源血缘 | 页面支持`wiki-claim`标记，Manifest记录Claim、来源ID和Chunk ID；删除共享来源时可自动删除独占Claim、保留共享Claim | 降低失效正文残留和整页重写成本 |
| 文档Diff局部更新 | 提取正文按段落形成内容寻址Chunk，工作单给出新增、删除、未变Chunk及受影响Claim | 小修改不必重新处理整份文档 |
| 页面身份匹配与去重 | BM25召回已有页面，标题/别名精确冲突在提交时直接拦截，语义候选交给Skill决定合并 | 减少重复概念页，同时避免程序误合并 |

旧页面仍兼容；页面被实际重写时才逐步增加Claim标记，不要求全库重建。

## 参考实现的本机量化结果

环境：参考实现本机 Python 3.11；中位数计时；不包含模型和网络。文档实验修改5%的段落。

| 规模 | Diff CPU耗时 | 后续输入文本减少 | nashsu公开策略全页扫描代理 | 当前Manifest直接定位 | BM25身份匹配/次 | 精确别名Recall@1 |
|---:|---:|---:|---:|---:|---:|---:|
| 100 | 0.048 ms | 95.03% | 0.021 ms | 0.0003 ms | 0.914 ms | 100% |
| 500 | 0.301 ms | 95.03% | 0.113 ms | 0.0002 ms | 4.620 ms | 100% |
| 1000 | 0.527 ms | 95.03% | 0.235 ms | 0.0002 ms | 9.620 ms | 100% |

Claim局部删除在1000页规模的实验中约0.88 ms。这些数字用于刻画本地确定性处理的复杂度趋势，不等同于模型 Token 账单，也不等同于真实语料事实准确率。

## 与nashsu的耗时结论

nashsu README公开的是SHA-256未变化跳过、两阶段LLM摄入、三重匹配级联删除，没有公布可直接复现的Wiki构建端到端耗时。因此不能诚实地写“当前方案比nashsu快X倍”。本报告的nashsu列是按README描述实现的**策略代理**，不是官方桌面程序跑分。

可以成立的结论是：

1. **修改范围更小。** nashsu检测到文件哈希变化后进入摄入流程；当前方案先做Chunk Diff。在5%段落变化实验中，后续新增文本输入减少95.03%，理论上可直接降低模型输入Token和等待时间。
2. **删除定位扩展性更好。** README描述的三重匹配需要检查Wiki页面；当前方案通过Manifest的来源倒排关系直接取得页面，再按Claim处理。绝对耗时都很小，但当前定位成本不随全库页面数线性扫描。
3. **当前端到端仍由模型主导。** 历史实测中，当前项目1份PDF生成2页约54秒，5份PDF生成10页约200秒；本地Diff不到1毫秒，优化收益最终取决于Skill是否严格只读取变化Chunk。
4. **nashsu真实端到端胜负暂未验证。** 要得到论文级结论，必须在同一电脑、同一模型、同一PDF、同一输出页数下运行两套系统，并记录模型调用次数和Token。没有这些条件时不报告虚假的倍数。

## 量化指标结论

| 指标 | 参考实现结果 | 结论边界 |
|---|---:|---|
| 小修改上下文减少率 | 95.03% | 合成文档，5%段落修改；不是模型Token账单 |
| Chunk Diff耗时 | 1000 Chunk为0.527 ms | 本地确定性处理 |
| Claim删除耗时 | 约0.88 ms | 100个Claim的合成页面 |
| 精确标题/别名去重Recall@1 | 100% | 合成精确别名集；同义概念仍需人工标注集验证 |
| 真实PDF端到端 | 1份约54秒；5份约200秒 | 历史观察值，受模型和网络影响 |
| nashsu真实端到端 | 暂无可比数据 | 官方README未提供同条件耗时 |

## 下一步实验

建立30份文档、20次修改、10次删除的人工标注集，重点测四项内容质量指标：删除完整率、误删率、页面重复率、错误合并率。随后用同一模型运行nashsu和当前项目，补齐端到端耗时、Token和模型调用次数，才能形成最终算法对比表。该实验由评测组在 `benchmarks/` 落地。
